Окно аутентификации / эксперимент

    

      Фронтенд по‑прежнему отправляет на backend access_token и произвольный
      user_id. В уязвимой реализации сервер доверял этому user_id
      и строил по нему сессию. В исправленной реализации сервер игнорирует
      user_id из браузера и определяет пользователя только по проверенному токену.

Симуляция атаки

        

          user_id жертвы (атакующий подставляет сюда чужой идентификатор,
          но использует свой токен). В исправленной версии сервера эта попытка больше
          не меняет сессию: сервер всё равно привяжет её к владельцу токена.

Обработка со стороны сервера

    

      Маршрут GET /me показывает, кого backend считает текущим
      пользователем. В уязвимой версии он мог показывать user_id жертвы.
      В исправленной версии он всегда показывает владельца проверенного токена,
      даже если в запросе на /login передавался поддельный user_id.
